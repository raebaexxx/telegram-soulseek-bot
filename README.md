# MusicBot — Telegram-бот для скачивания музыки из сети Soulseek

Бот ищет треки в P2P-сети **Soulseek** (той самой, которую использует приложение
[Seeker](https://github.com/jackBonadies/SeekerAndroid) для Android) и присылает лучшие
варианты прямо в Telegram.

Реализация на **C#/.NET 8** поверх библиотеки **Soulseek.NET** — той же, на которой построен Seeker.

## Как это работает

```
Ты: «Radiohead Creep»
        │
        ▼
   /search ──► Soulseek-сеть ──► ответы пиров (MP3/FLAC/…)
        │
        ▼
  Топ-8 кнопок в чате (качество, битрейт, размер, скорость пира)
        │
        ▼
  Жмёшь кнопку ──► файл скачивается (прогресс в чате) ──► аудио приходит в Telegram
```

Результаты ранжируются автоматически: lossless (FLAC/WAV) выше lossy, выше битрейт — лучше,
плюс бонусы за скорость пира и свободный upload-слот.

## Возможности

- Поиск обычным текстом, без команд: просто напиши запрос
- **Альбомы**: папки пиров группируются и предлагаются целиком — одной кнопкой
- Топ-8 результатов кнопками, с автоматическим скорингом качества
- Прогресс скачивания прямо в чате (проценты, скорость, оставшееся время)
- **Альбомы приходят треками по мере скачивания**: первый трек — через несколько секунд,
  слушать можно сразу, не дожидаясь конца и без распаковки архивов
- У треков читаются настоящие теги из файла (ID3/Vorbis): исполнитель, название, альбом,
  длительность и встроенная обложка становятся превью в Telegram
- Если нужен архив — переключи `Albums:PackageAs` на `zip` или `both`
- Очередь: до 2 параллельных скачиваний (`Downloads:MaxConcurrent`)
- `/cancel` — отмена текущей загрузки (в том числе альбома), `/status` — состояние очереди
- **Шаринг** папки загрузок: без этого сеть считает бота «леечером» и режет скорость
- Автопереподключение к Soulseek при обрывах
- Поддержка файлов >50 МБ через локальный Bot API сервер (до 2 ГБ)
- Whitelist: бот работает только с одним Telegram-пользователем

## Требования

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- Аккаунт **Soulseek** — бесплатная регистрация на <https://www.slsknet.org/register>
  (привилегии за ~$5 необязательны, но заметно ускоряют поиск и качает)
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)
- Для файлов >50 МБ — локальный [telegram-bot-api](https://github.com/tdlib/telegram-bot-api) (необязательно)

## Установка

```bash
git clone <репозиторий> musicbot
cd musicbot
dotnet build -c Release
```

## Настройка

Файл с секретами (`src/MusicBot/appsettings.json`) в репозиторий **не попадает** — вместо него
лежит шаблон. Скопируй его и заполни:

```bash
cp src/MusicBot/appsettings.example.json src/MusicBot/appsettings.json
```

Всё в одном файле — `src/MusicBot/appsettings.json`:

```json
{
  "Telegram": {
    "Token": "123456:ABC...",              // токен от @BotFather
    "AdminUserId": 123456789,             // твой Telegram ID (команда /id узнает)
    "LocalApiBaseUrl": ""                 // "" = официальный сервер (лимит 50 МБ)
  },
  "Soulseek": {
    "Username": "твой_логин",
    "Password": "твой_пароль",
    "ListenPort": 50000,
    "DownloadDirectory": "downloads",     // эта же папка шарится сети
    "ShareDownloads": true,
    "ShareDescription": "Music sharing via Telegram bot"
  },
  "Search": {
    "TimeoutSeconds": 10,                 // сколько ждём ответов пиров
    "ResponseLimit": 100,
    "MaxResultsShown": 8
  },
  "Downloads": {
    "MaxConcurrent": 2,                   // параллельных скачиваний
    "MaxUploadSlots": 2,                  // сколько слотов отдаём сети
    "KeepDownloadedFiles": true,          // false = удалять сразу после отправки
    "StallTimeoutSeconds": 20,            // нет передачи N секунд → искать другого пира
    "MaxDiskUsageGb": 10,                 // предел папки загрузок; 0 = неограниченно
    "MinFilesToKeep": 10,                 // столько свежих файлов не удаляем (нужно для шары)
    "CleanupIntervalMinutes": 10,         // как часто проверять объём
    "MinFileAgeMinutes": 15               // файлы моложе не удаляем (могут ещё отправляться)
  },
  "Albums": {
    "MinFilesForAlbum": 3,                // меньше файлов в папке — это не альбом
    "MaxAlbumsShown": 5,                  // сколько альбомов показывать
    "MaxAlbumsPerPeer": 2,                // иначе топ из одного пира
    "MaxTracksPerAlbum": 60,              // защита от «альбомов» на 500 файлов
    "ParallelTracks": 1,                  // треки подряд; 2-3 — только если у пира есть слоты
    "PackageAs": "individual",            // individual (треками) | zip | both
    "MaxZipSizeMb": 1800                  // больше — отправим треки по одному
  }
}
```

### Как приходят альбомы

По умолчанию (`PackageAs: individual`) треки отправляются в чат **по мере скачивания**:
первый трек обычно через 10–30 секунд, дальше следом. Каждый — отдельным аудио с тегами
исполнителя, альбомом, длительностью и обложкой из самого файла, так что его сразу видно
и слышно в плеере Telegram. Отправка ограничена ~20 сообщениями в минуту, чтобы не ловить
флуд-лимит.

`PackageAs: zip` — как раньше, одним архивом в конце. `both` — треки плюс архив.

Тот же формат можно переопределить переменными окружения, например
`Telegram__Token=...` или `Soulseek__Password=...`.

## Запуск

Одна команда поднимает всё: локальный Bot API сервер (если он включён в конфиге) и самого бота.
`Ctrl+C` останавливает оба процесса.

```bash
cd ~/projects/musicbot
./run.sh
```

Остановить — либо `Ctrl+C` в том же окне, либо из другого:

```bash
./run.sh stop
```

Что происходит под капотом:
1. Проверяются порты `8081` (локальный API) и `50000` (слушатель Soulseek) — если заняты,
   скрипт скажет «бот уже запущен» и выйдет, а не уронит всё с крашем.
2. Поднимается `telegram-bot-api`, скрипт ждёт готовности порта.
3. Запускается бот, его логи идут в консоль.
4. По `Ctrl+C` оба процесса корректно завершаются.

Логи локального сервера пишутся в `logs/telegram-bot-api.log`.

1. Напиши боту `/id` — он покажет твой user id.
2. Впиши его в `AdminUserId` и перезапусти (пока стоит 0 — бот отвечает всем, есть предупреждение в логах).
3. Напиши любой запрос, например `Radiohead Creep`, выбери результат кнопкой.

### Файлы больше 50 МБ (FLAC альбомов и т.п.)

Официальный Bot API принимает максимум 50 МБ. Для больших файлов нужен локальный сервер.

1. Получи `api_id` / `api_hash` на <https://my.telegram.org> → Tools → API development tools.
   (Application title и Short name — любые, платформа — Other)
2. Сохрани ключи в файл (он не попадёт в git):

   ```bash
   cp scripts/telegram-bot-api.env.example scripts/telegram-bot-api.env
   # впиши в него:
   #   TELEGRAM_API_ID=12345678
   #   TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
   ```

3. Собери сервер:

   ```bash
   git clone https://github.com/tdlib/telegram-bot-api.git ~/telegram-bot-api
   cd ~/telegram-bot-api
   cmake -B build -DCMAKE_BUILD_TYPE=Release
   cmake --build build -j$(nproc)
   cp build/telegram-bot-api .
   ```

4. **Важно:** раз токен был привязан к api.telegram.org, его нужно снять с официального сервера
   (иначе локальный сервер его не примет):

   ```bash
   cd src/MusicBot
   dotnet run -- logout
   ```

5. Укажи базу в `appsettings.json`:

   ```json
   "LocalApiBaseUrl": "http://127.0.0.1:8081/bot"
   ```

Дальше ничего делать не нужно: `./run.sh` сам поднимет локальный сервер перед ботом
и остановит его по `Ctrl+C`. Отдельно `./scripts/run-telegram-bot-api.sh` запускать не требуется.

Ключи можно передать и без файла:
`TELEGRAM_API_ID=… TELEGRAM_API_HASH=… ./run.sh`

Переменные окружения имеют приоритет над файлом — это удобно, например, в systemd-юните,
где пути задаются через `Environment=`.

### Если сервер не запускается: «CPU ISA level is lower than required»

Ошибка означает, что бинарь собран под более новый процессор, чем на сервере: в ELF-метке
указано `x86-64-v4` (AVX-512), которого на Xeon Broadwell и старше нет. Проверь:

```bash
readelf -n telegram-bot-api | grep "ISA needed"
objdump -d telegram-bot-api | grep -c "%zmm"    # 0 — реальных AVX-512 инструкций нет
```

Если реальных инструкций нет, а метка осталась (так бывает у тулчейна Arch), метку можно
снять, и бинарь будет работать на старых CPU:

```bash
objcopy --remove-section=.note.gnu.property telegram-bot-api telegram-bot-api-fixed
```

Локальный сервер лучше держать на 127.0.0.1 и не прображивать наружу.

## Сеть: почему важен шаринг

Soulseek — взаимная сеть. Пиры, которые только качают («леечеры»), получают жёсткие ограничения:
пропускные способности режутся, в очередях их пропускают. Поэтому бот:

- шарит папку `downloads` (поиск, просмотр, user info),
- объявляет реальное число upload-слотов (`Downloads:MaxUploadSlots`),
- отвечает на поиски других, кроме файлов с «запрещёнными фразами», которые сервер Soulseek
  присылает автоматически (антикопирайтный фильтр).

Оставь `KeepDownloadedFiles: true` — иначе шара останется пустой. Старые файлы можно
периодически чистить: наполнение шары обновляется после каждого скачивания.

## Скорость: как получить быструю закачку

Замеры показывают, что проблема обычно не в боте, а в том, могут ли пиры **достучаться до тебя**.

Soulseek работает так: ты просишь файл у пира, а пир **сам подключается к тебе** по адресу,
который сервер Soulseek знает о тебе. Если ты за NAT или трафик идёт через VPN/туннель,
пир подключиться не может — и закачка либо виснет, либо идёт очень медленно.

Что проверить:

1. **Проброс порта.** На роутере сделай проброс TCP-порта `Soulseek:ListenPort` (50000)
   на локальный IP машины с ботом. Если IP machines меняется — закрепи его в DHCP.
   Тогда пиры смогут заходить к тебе напрямую, и скорость вырастет в разы.
2. **VPN/туннель.** Если весь трафик идёт через прокси (Xray, WireGuard и т.п.), сервер
   Soulseek видит адрес туннеля, а не твой домашний — входящие соединения невозможны.
   Добавь правило «bot → direct» (исключение для процесса или для порта 50000) либо запускай
   бота без туннеля.
3. **Права аккаунта.** Привилегии Soulseek (разовый донат ~$5) поднимают приоритет в очередях.
4. **Шара.** Пока папка `downloads` пуста, сеть считает бота леечером и режет скорость.
   Скачай хо бы что-то — и в логах появится `объявлено N папок / M файлов в шаре`.

Что уже сделано в боте на случай плохой сети:

- **Переключение между пирами.** К каждому треку приклеиваются до 3 запасных пиров с тем же
  треком (для альбомов ищутся копии в одноимённых папках). Если за
  `Downloads:StallTimeoutSeconds` (по умолчанию 20) не пришло ни байта, бот бросает текущего
  пира и пробует следующего — сам, без `/cancel`. Если запасных пиров нет, ждёт в 1.5 раза дольше.
- **Последовательная закачка треков альбома** (`Albums:ParallelTracks: 1`). Параллельные запросы
  к одному пиру упираются в его upload-слоты: остальные висят и тратят таймауты впустую.
  Значение 2-3 имеет смысл, только если у пира несколько свободных слотов.
- **Упорядоченная выдача.** Треки уходят в чат строго по номерам, даже если скачались не по
  порядку; битый трек не блокирует альбом — через 10 секунд бот идёт дальше.
- **Проверка целостности.** Размер скачанного сверяется с заявленным, битый файл удаляется.
- **В логах видна фактическая скорость:** `Скачано: … за 42с — 4.40 МБ/с`.

Замеры на одной и той же машине и сети:

| Пир | Результат |
|---|---|
| `trueold89` | 4 трека подряд: 4.7 / 7.6 / 4.7 / 4.8 МБ/с |
| `KalorXD` | 1.1 МБ/с, часть треков отвалилась по таймауту |
| `OvervalueSkipping7` | 0 байт за 20 секунд (пир не смог достучаться) |

Вывод: скорость определяется тем, может ли пир подключиться к тебе. Проброс порта и исключение
туннеля поднимают скорость у всех пиров сразу.

## Команды

| Команда | Что делает |
|---|---|
| любой текст | поиск по сети |
| `/search <запрос>` | явный поиск (то же, что просто текст) |
| `/start`, `/help` | справка |
| `/cancel` | отменить текущее скачивание |
| `/status` | очередь + сколько места занято в папке загрузок |
| `/cleanup` | подрезать папку загрузок до лимита |
| `/id` | показать свой Telegram ID |

## Место на диске

Скачанные файлы **не удаляются сразу**: пустая шара — это статус «леечер» в сети Soulseek,
там режут скорость и не берут в очередь. Поэтому бот держит папку загрузок в границах:

- `Downloads:MaxDiskUsageGb` — предел объёма (по умолчанию 10 ГБ, `0` = без ограничений)
- `Downloads:MinFilesToKeep` — сколько свежих файлов не трогать даже при переполнении
  (по умолчанию 10, чтобы шара не опустела)
- `Downloads:MinFileAgeMinutes` — файлы моложе этого не удаляются (могут ещё отправляться в Telegram)

Фоновая проверка каждые `CleanupIntervalMinutes` удаляет самые старые файлы, пока объём
не уйдёт под лимит. Ручной запуск — `/cleanup` или `/status`, чтобы посмотреть занятое место.

## Диагностика

- Логи идут в консоль; полезные строки: `Soulseek: вход выполнен`, `Поиск «…»: N ответов`,
  `Скачано: …`
- `401 Unauthorized` от Telegram — неверный токен либо нужен `dotnet run -- logout` для локального сервера
- `Порт 50000 занят — скорее всего, бот уже запущен в другом окне` — останови лишний экземпляр:
  `./run.sh stop`
- `Порт 8081 уже занят` (от скрипта Bot API) — сервер уже работает, второй не нужен
- `Сервер Soulseek отклонил логин или пароль` — проверь `Soulseek:Username` / `Soulseek:Password`
- `ListenException` — порт `Soulseek:ListenPort` занят другим процессом; смени порт в конфиге
- Поиск не находит ничего — проверь, что вход в Soulseek прошёл (строка «вход выполнен»)
- Скачивание висит — у пира нет свободных слотов; попробуй другой результат из списка

## Правовая заметка

Soulseek — P2P-сеть, значительная часть контента в ней защищена авторским правом.
Бот сделан для личного использования (whitelist одного пользователя). Ты отвечаешь
за то, что скачиваешь, и за соблюдение законов своей страны.
